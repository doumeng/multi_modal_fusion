# 配对毫米波点云生成距离直方图：可行性分析

日期：2026-09-20。依据：用户已同意现有倾斜下视模拟参数，并提出同时研究配对雷达数据路线。本报告已核查官方网页，尚未下载或解析真实数据文件。

## 结论

建议保留两条互补路线，而不是用其中一条完全替代另一条：

- A：无人机红外 + 假设几何生成的统计雷达，用于目标场景的流程调试和可控退化实验。保留高度 60 m、下视角 45°、水平视场 60°、[0,256) m 量程及 200 回波。
- B：真实配对红外 + 毫米波点云，汇聚为距离直方图，用于检验真实跨模态相关性。优先核验 FlexSense。

B 减少了直接从车辆真值构造输入的风险，证据质量优于标签条件化模拟；但它仍是“检测点云距离统计代理”，不能恢复原始回波计数，也不能将路侧视角改名为无人机视角。

## “截取对应位置”的三种含义

1. **固定共同视场：首选。** 使用雷达到相机外参、相机内参和图像边界筛选雷达点，保留共同视场内的背景与目标。不得用真值框筛选输入。
2. **图像检测器预测区域：后续研究。** 只可使用推理时也能获得的预测，训练阶段宜采用折外预测以减少乐观偏差。该路线会受红外漏检限制，并增加候选区域依赖，首版不采用。
3. **真值车辆框或人工选定目标区域：仅诊断。** 可用于研究车辆距离分布或理想关联上限，不能作为实际融合性能主实验的输入生成方式。

固定共同视场筛选本身也借用了原始点云的角度信息。若未来真实设备只输出不可裁剪的一维直方图，必须保证它的天线有效视场与此筛选近似一致，否则存在传感器能力差异。建议同时保留全雷达视场与共同视场两个版本做消融。

投影进入图像边界不代表该点在光学图像中可见；遮挡、穿透/多径和标定误差仍然存在。首版不利用标签替用户清除这些困难样本。

## 转换流程

1. 审计雷达点字段、单位、坐标轴、是否已增强/累积/跟踪，以及时间戳。优先使用单帧检测点，不能把轨迹目标中心、增强点云或 LiDAR 当成原始雷达检测点。
2. 依据实际标定将雷达点转换至相机坐标，按与图像一致的畸变/去畸变模型投影。相机后方、非有限点和视场外点按原因统计。
3. 通过实际时间戳检查同步；超出配置容差时标记无配对，不能仅按文件排序硬拼。
4. 在原始雷达坐标系计算斜距 `r=sqrt(x*x+y*y+z*z)`，按固定米制距离边界统计。用于视场筛选的相机坐标和用于斜距的雷达原点不能混用。
5. 保留全部有效目标和背景，不根据速度阈值默认删除静止点，否则可能删除停放车辆。
6. 原始汇聚先输出 `raw_counts` 与 `source_point_count=M`。记录全视场、共同视场、量程内等各筛选阶段点数。
7. 为匹配现有模型接口，非空样本再生成固定 200 次统计重采样版本。

若输入只有投影深度图，先确认存储值是相机 Z 深度、雷达斜距还是其他编码。相机 Z 深度不能直接当作雷达斜距。即便有完整标定可以反投影，多点落在同一像素导致的重数丢失仍无法凭空恢复。因此优先读取原始点云。

不要将路侧点云坐标简单旋转到 45° 并抬高 60 m 就声称获得无人机配对数据：观测点支持、遮挡、散射强度和对应红外视角都不会随坐标变换自动重建。

## 固定 200 与真实点数的处理

真实帧的有效点数 M 不一定等于 200。建议明确输出两种产品：

    raw_counts[k] = 有效点斜距落在第 k 桶的点数
    sum(raw_counts) = M
    p[k] = raw_counts[k] / M                 # 仅 M > 0
    proxy_counts_200 ~ Multinomial(200, p)

`proxy_counts_200` 必须标为“点云经验分布重采样”，不是 200 个独立的实测回波。少于 200 个点时重复抽取不会增加信息；多于 200 时会丢失部分统计信息。保存种子、M、非空桶数及原始计数，报告稀疏程度。

空帧 M=0 时，200 次重采样无定义。使用全零占位和 `radar_valid=false`，不伪造均匀回波；这不是符合 200 计数约束的有效雷达样本。保留该红外帧以评价模态缺失；单独统计缺失率，禁止只报告非空帧的性能。

用 `raw_counts/M` 与 `proxy_counts_200/200` 做对照，检验固定计数重采样的影响。M 只用于诊断和分组评价，首版不作为额外网络输入，以免比较中悄悄引入不同信息。

128 桶由相邻 256 桶相加获得，保持相同量程和同一次重采样结果。真实数据是否主要落在少数近距离桶应由数据统计判断，不因看到验证集效果而调整量程。

不以多帧无补偿拼接来凑 200 点。后续若研究积累，需要同时处理自运动、目标运动和时间窗口长度。

## 联合实验安排

| 实验 | 目的 | 可支持的结论 |
| --- | --- | --- |
| A1 无人机红外单模态 vs 统计模拟融合 | 几何/网络接口和受控条件验证 | 模拟设定内能否利用辅助信息 |
| B1 同一配对数据集红外 vs 点云距离汇聚融合 | 真实跨模态对应 | 路侧/地面采集场景的代理直方图是否有用 |
| B2 原始经验频率 vs 200 重采样 | 分析固定输入要求的影响 | 计数重采样带来的损失或方差 |
| B3 全视场 vs 共同视场；配对 vs 分组打乱 | 检查角度筛选、同步及场景捷径 | 模型收益是否依赖额外预处理或真实配对 |
| B4 128 vs 256；空帧/稀疏帧/密集帧 | 表示选择与鲁棒性 | 收益出现在哪些点数和分辨率条件 |

所有比较在同一个数据集、划分和训练预算内进行。不得把不同数据集上的 mAP 差直接解释成融合提升。

A 和 B 分别报告，不将无人机图像与无关路侧雷达帧拼成“真实配对”。未来若做跨域预训练，可先在 B 学习融合，再到 A 微调；但只有 A 的模拟评估仍不能证明无人机真实雷达有效。

## 推进顺序

1. 按已确认设计完成倾斜下视统计模拟器与可视化。
2. 优先审计 FlexSense 的一段训练序列：同步、标定、点字段、车辆标注、有效点数、距离占用率及空帧比例。
3. 数据审计合格后实现点云适配器和双版本直方图；若不合格，记录原因后选择 NTU4DRadLM 等替代候选，不降低配对真实性要求。
4. 跑红外与融合对照；数据集相关事实以下载后的审计报告为准。

本次不声称已获取数据、恢复回波、实现转换器或得到性能增益。实施计划仅针对已确认的模拟器；真实数据适配器的字段映射在小样本审计后确定。
